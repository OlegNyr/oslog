# oslog

[English](README.md) · **Русский**

Просмотр логов Spring Boot (ECS / `FormatterElastic`) прямо из OpenSearch — без Dashboards. Те же список, таймлайн, фильтры, детали и панель «Обмен», что во вьювере `logview`, плюс строка запроса к OpenSearch и локальный кэш: однажды загруженное открывается мгновенно и без сети.

![Главное окно: matrixkc и acd в одной ленте, детали ответа с панелью «Обмен»](docs/images/main.png)

## Запуск

1. Скачайте **[oslog-portable.exe](https://github.com/OlegNyr/oslog/releases/download/latest/oslog-portable.exe)** — последняя сборка, один файл, установка не нужна. Ссылка постоянная: каждая новая сборка заменяет файл по ней.
2. Запустите. Первый старт занимает несколько секунд: файл распаковывается во временную папку.
3. Windows может показать «Windows защитила ваш компьютер» (SmartScreen): файл не подписан. Нажмите **Подробнее → Выполнить в любом случае**.

## Первая настройка

При первом запуске откроется окно настроек (потом — кнопка **⚙** в правом верхнем углу):

- **URL** — адрес OpenSearch, например `https://opensearch.example:9200`;
- **логин и пароль** — ваши личные;
- **CA-сертификат** — путь к `.pem`, если сертификат кластера выдан внутренним центром сертификации, которого нет в хранилище сертификатов Windows. Обычно не нужен: корпоративные корневые сертификаты из Windows подхватываются сами. «Не проверять сертификат» — только если ничего другое не помогло;
- **индекс по умолчанию** — `plchat-k8s-prod-*`;
- **кэш** — сколько дней хранить (по умолчанию 7) и максимальный размер (2 ГБ).

Нажмите **проверить соединение** — должно появиться «есть соединение · N записей за 15 мин». Затем **сохранить**.

## Как пользоваться

Верхняя строка — запрос к OpenSearch:

- **индекс**;
- **сервисы** (`matrixkc`, `acd`) — клик включает/выключает, можно включить несколько: логи сольются в одну ленту по времени, появится колонка «service». **+** — добавить сервис, правый клик — убрать;
- **интервал** или быстрые кнопки **15м / 1ч / 6ч / 24ч** — они считают от текущего момента при каждой загрузке и сразу загружают;
- **запрос Lucene** (необязательно), например `app.level:ERROR` или `app.traceId:30fcbc00…`;
- **лимит** — сколько записей загрузить максимум (по умолчанию 5 000), берутся самые свежие;
- **загрузить** (или Enter в любом поле); во время загрузки кнопка становится **стоп** — загруженное к этому моменту покажется.

Справа от строки — что получилось: «7 950 записей (из кэша 7 607, из OpenSearch 343)», «достигнут лимит», ошибки (неверный пароль, нет сети, ошибка в запросе Lucene).

**Гистограмма плотности.** Над таймлайном — сколько записей в OpenSearch по всему интервалу запроса, а не только среди загруженных: снизу столбика ERROR (красный), выше WARN (жёлтый). Если сработал лимит, незагруженная часть интервала затемнена, а в подписи — «в OpenSearch: N · загружено: M». Наведите на столбик — его время и числа. **Протяните мышью** по гистограмме — этот интервал встанет в строку запроса и загрузится; так удобно приближаться к всплеску. Для файлов, CSV и трейса гистограммы нет; она всегда запрашивается из OpenSearch, без сети не показывается.

**Весь трейс.** В деталях записи под `traceId` есть кнопка **⤓ весь трейс**: она загружает из OpenSearch все записи этого трейса по **всем** сервисам (не только включённым) в пределах ±1 часа от записи. Клик по самому значению `traceId`, как и раньше, фильтрует уже загруженное. Вернуться к обычной выборке — **загрузить**.

![Весь трейс: записи acd и matrixkc одного traceId, таймлайн по спанам](docs/images/trace.png)

**Сортировка.** Клик по заголовку колонки (time, level, logger, thread, message, service и любые добавленные колонки) — сортировка по ней: ▲, ещё клик — ▼, ещё — как было загружено. **Shift+клик** добавляет следующую колонку к сортировке (в заголовке появятся номера ▲1, ▲2…), повторный Shift+клик меняет её направление или убирает. Например: level, потом service, потом time ▼ — сначала ошибки, внутри по сервисам, внутри свежие сверху. Числа в колонках (например, `duration`) сравниваются как числа.

Ниже — всё, как во вьювере: поиск по загруженному (`/`), интервал, уровни, **▲ / ▼ issue** (Shift+P / Shift+N), колонки, export, таймлайн трейсов, детали записи. В деталях у каждого поля есть **⊕** (фильтр по значению) и **▦** (вывести колонкой), в том числе для полей Kubernetes — сервис, под, нода. Открыть `.log`-файл или вставить ndjson (Ctrl+V) тоже можно.

**CSV-экспорт из OpenSearch Dashboards** (Discover → Share / Reporting → CSV) открывается так же — кнопкой «open file…», перетаскиванием или вставкой. В экспорте должна быть колонка `message`: в ней исходная строка лога, из неё берётся всё остальное. Если в экспорт попали `@timestamp`, `pod_labels.app`, `pod`, `namespace`, `container`, `node`, `k8sClusterName`, они тоже подхватятся (сервис, под, нода в деталях и колонкой). Записи сортируются по времени; несколько файлов, в том числе CSV вперемешку с `.log`, сливаются в одну ленту.

## Кэш и работа без сети

- Запросы **без Lucene** кэшируются: повторный или пересекающийся запрос берёт уже загруженное с диска и докачивает из OpenSearch только недостающее. Последние 5 минут всегда запрашиваются заново — OpenSearch их ещё дописывает.
- Запросы **с Lucene** и **весь трейс** всегда идут в OpenSearch и в кэш не попадают.
- Без сети запросы без Lucene показывают то, что есть в кэше за этот интервал, с пометкой об ошибке.
- Старые записи удаляются сами (по сроку хранения и размеру). **Очистить кэш** — в настройках.

## Где что хранится

Всё в `%APPDATA%\oslog\`, у каждого пользователя своё, в `.exe` ничего не зашито:

- `settings.json` — настройки (без пароля);
- `password.bin` — пароль, зашифрованный средствами Windows (DPAPI): расшифровать его можно только под вашей учётной записью на этом компьютере;
- `cache.db` — кэш загруженных логов.

В логах есть боевые данные (matrix id, IP, URL). Приложение обращается только к указанному OpenSearch и больше никуда; загруженное лежит только в `cache.db`. Если компьютер чужой или общий — очистите кэш.

## Если не работает

| Сообщение | Что делать |
|---|---|
| `401: неверный логин или пароль` | Проверьте логин и пароль в настройках. |
| `403: нет прав на индекс` | Нужны права на чтение индекса — к администраторам OpenSearch. |
| `сертификат не доверен…`, `неизвестный издатель сертификата` | Укажите CA-сертификат (`.pem`) в настройках. |
| `адрес не найден (DNS)`, `соединение отклонено`, `таймаут` | Проверьте URL и что вы в сети/VPN. |
| `сбой на N из M шардов: … Failed to parse query` | Ошибка в запросе Lucene. |
| `404: index_not_found_exception` | Проверьте имя индекса. |

## Для разработчиков

Требуется Node 24. `npm install`, `npm start` — сборка страницы и запуск. `npm run dist` — `dist/oslog-portable.exe` (собирать на Windows или в CI: `.github/workflows/build.yml` на каждый push в `main` собирает `.exe` и заменяет им единственный релиз `latest`). Локальный OpenSearch с тестовыми данными — в `dev/`. Устройство и правила — в `CLAUDE.md` и `docs/PLAN.md`. Скриншоты сняты на синтетических данных из `dev/load-synthetic.js`.
