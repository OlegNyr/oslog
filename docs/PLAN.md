# oslog — план

Настольное приложение (Electron) для просмотра логов Spring Boot / ECS из OpenSearch. Интерфейс — форк вьювера из проекта `logview` (список, таймлайн, фильтры, «Обмен», детали), источник данных — OpenSearch, с локальным кэшем в SQLite. Отдельный проект и репозиторий.

Образцы запроса и ответа OpenSearch Dashboards: `docs/request.json`, `docs/response.json`.

## 1. Решения

- **Electron**, без прокси: запросы к OpenSearch делает основной процесс, CORS не мешает.
- **Прямой доступ** к OpenSearch с логином и паролем; у каждого пользователя свои.
- **Сервисы:** `matrixkc` и `acd` (`pod_labels.app`), список можно дополнять.
- **Интерфейс:** строка запроса к OpenSearch + все фильтры и кнопки вьювера `logview`.
- **Кэш:** SQLite на диске, можно смотреть без сети.
- **Раздача:** коллегам — portable `.exe` для Windows.

## 2. Структура проекта

```
oslog/
  package.json          electron, electron-builder (devDependencies)
  build.js              собирает страницу из src/ в app/renderer/index.html
  src/                  страница (форк logview/src)
    index.html          + строка запроса OpenSearch, окно настроек
    styles.css
    js/NN-*.js          фрагменты вьювера + свои (opensearch, settings, cache-status)
  app/
    main.js             окно, IPC-обработчики
    preload.js          мост window.osApi (contextBridge)
    opensearch.js       HTTP-клиент OpenSearch (basic auth, CA, пагинация)
    cache.js            SQLite-кэш
    settings.js         настройки в userData, пароль через safeStorage
    renderer/           собранная страница (генерируется)
  docs/
```

`src/` и `build.js` уже скопированы из `logview` (коммит `5c4ba9b`), там же описание архитектуры и схемы логов — `docs/logview-CLAUDE.md`. `build.js` пока собирает `log-viewer.html` в корень; на этапе 1 переделать на `app/renderer/index.html`. Вьювер копируется один раз и дальше развивается отдельно: те же правила (ES5-стиль, `esc()` для всего из логов, виртуальный список с фиксированной высотой строки).

## 3. Безопасность Electron

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- CSP: только локальные ресурсы, никаких внешних скриптов и шрифтов.
- Страница видит только `window.osApi` с узким набором методов: `search`, `getSettings`, `saveSettings`, `testConnection`, `cacheStats`, `clearCache`. Произвольный HTTP или файловая система недоступны.
- Основной процесс проверяет аргументы: имя индекса по шаблону (`[\w.*,-]+`), только `_search`, лимиты на размер.
- Пароль не возвращается в страницу; хранится зашифрованным через `safeStorage` (в Windows — DPAPI, привязка к учётной записи).

## 4. Настройки

Окно настроек при первом запуске и по кнопке ⚙:

- URL OpenSearch (`https://…:9200`);
- логин и пароль, кнопка «проверить соединение»;
- CA-сертификат (путь к `.pem`) или галочка «не проверять сертификат»;
- индекс по умолчанию (`plchat-k8s-prod-*`);
- кэш: срок хранения (по умолчанию 7 дней), максимальный размер (2 ГБ), кнопка «очистить».

Хранятся в `userData/settings.json` (`%APPDATA%/oslog/` в Windows), пароль — отдельно, зашифрованным.

## 5. Строка запроса

- **индекс** (по умолчанию из настроек);
- **сервисы** — кнопки-переключатели `matrixkc` и `acd`, можно включить оба (логи сливаются в одну ленту по времени); «+» — добавить, правый клик — убрать;
- **интервал от/до** и быстрые кнопки **15м / 1ч / 6ч / 24ч**;
- **запрос Lucene** (необязательно), например `app.traceId:30fc…` или `app.level:ERROR`;
- **лимит** записей (по умолчанию 5000);
- кнопка **«загрузить»**, во время загрузки — **«стоп»** (загруженное показывается);
- строка состояния: прогресс («загружено 3 000 из 12 345…»), сколько из кэша и сколько из OpenSearch, ошибки (401, нет сети, ошибка в Lucene-запросе).

Значения запоминаются между запусками. Enter в любом поле — поиск.

Ниже — всё, что есть во вьювере `logview`: поиск и интервал по загруженному, уровни, ▲/▼ issue, колонки, export, чипы, таймлайн, детали, «Обмен», ⊕/▦. Работают локально по загруженному набору. Открытие `.log`-файлов и вставка ndjson тоже остаются.

## 6. Запрос к OpenSearch

Пример из Dashboards упрощается:

- **условия:** `range @timestamp` (epoch_millis) + `pod_labels.app` — любой из выбранных (`bool.should` из `match_phrase`, `minimum_should_match: 1`) + `query_string`, если задан;
- **поля:** `_source` = `@timestamp`, `message`, `pod_labels.app`, `pod`, `namespace`, `container`, `node`, `k8sClusterName`. Без `highlight`, `docvalue_fields`, `stored_fields`;
- **порядок:** `sort @timestamp desc`, `track_total_hits` на первой странице;
- **пагинация:** страницы по 1000; следующая — та же выборка с `lte` = время последней записи, дубликаты отбрасываются по `_index/_id`. Записи с одинаковым временем на стыке не теряются, работает на любой версии OpenSearch;
- **остановка:** набран лимит, данные кончились или нажат «стоп».

## 7. Хит → запись вьювера

- `_source.message` — исходная ndjson-строка от `FormatterElastic`, идёт в `norm()` без изменений.
- К записи добавляется `parsed.k8s = {app, pod, namespace, container, node, cluster}`; сервис и под попадают в строку поиска. Через ⊕/▦ — фильтр и колонка по сервису и поду.
- `message` не JSON (баннер Spring и т. п.) → запись `RAW`, время берётся из `@timestamp` хита.
- Сортировка по времени из лога, при равенстве — по `sequenceNumber`.
- `loadText()` во вьювере делится на разбор и `setRecords(recs, name, what)`, чтобы загружать готовые записи.

## 8. Локальный кэш (SQLite)

**Где:** `userData/cache.db`.

**Чем:** встроенный `node:sqlite` (без нативной сборки). Первым делом проверить, что он доступен в Node внутри текущего Electron; если нет — `better-sqlite3` с пересборкой под Electron (`electron-builder install-app-deps`).

**Таблицы:**

- `hits(pattern, key, app, ts, raw, meta, fetched_at)`, ключ `(pattern, key)`, где `key` = `index/_id`, а `pattern` = `URL кластера|шаблон индекса` — один документ под разными шаблонами или кластерами не перетирает чужие строки; индекс `(pattern, app, ts)`; `ts` — `@timestamp` хита (по нему идёт `range`), `raw` — `message`, `meta` — k8s-поля в JSON;
- `coverage(pattern, app, from_ms, to_ms)` — какие интервалы загружены полностью, соседние сливаются.

**Запрос без Lucene:**

1. Для каждого сервиса вычесть из `[от, до]` покрытые интервалы → список недостающих кусков.
2. Докачать недостающие куски из OpenSearch, записать хиты.
3. Отметить покрытие только для того, что скачано полностью. При обрыве по лимиту или «стоп» покрыт кусок `(время последней записи, до]` — загрузка идёт от новых к старым; сама миллисекунда последней записи не отмечается, её записи могли попасть не все.
4. Свежий хвост (последние 5 минут) не отмечать покрытым: в OpenSearch он ещё дописывается.
5. Отдать записи из SQLite за `[от, до]`, последние `лимит` штук.

**Запрос с Lucene:** всегда в OpenSearch, в кэш не пишется — иначе пришлось бы хранить результаты каждого запроса отдельно.

**Очистка:** при старте и раз в час — удалить хиты старше срока хранения, при превышении размера — самые старые; покрытие подрезается вместе с ними. Кнопка «очистить кэш» в настройках.

**Без сети:** запросы без Lucene отдаются из кэша по тому, что покрыто, с пометкой в строке состояния.

## 9. Сборка и раздача

- Разработка: `npm install`, `npm start` (`node build.js` + `electron .`). В WSL окно Electron открывается через WSLg (Windows 11).
- Раздача: `electron-builder --win portable` → один `oslog.exe` (~90–100 МБ). Собирать на Windows или в CI на `windows-latest`.
- Неподписанный `.exe`: SmartScreen предупредит, корпоративный антивирус может блокировать. Варианты: корпоративный сертификат подписи кода; или раздавать zip с распакованным приложением (`--win dir`). Уточнить у ИБ.
- Настройки, пароль и кэш у каждого коллеги свои (`%APPDATA%/oslog/`), в `.exe` ничего не зашивается.
- Автообновление — не в первой версии.

## 10. Этапы

1. **Каркас:** Electron-окно, `build.js`, форк вьювера, `setRecords()`, настройки с `safeStorage`, «проверить соединение».
2. **Поиск:** строка запроса, сервисы, пагинация, «стоп», k8s-поля, ошибки.
3. **Кэш:** SQLite, покрытие интервалов, докачка недостающего, очистка, работа без сети.
4. **Раздача:** portable `.exe`, CI на `windows-latest`, README для коллег.

## 11. Потом

- Клик по `traceId` — загрузить весь trace по всем сервисам.
- Гистограмма плотности по всему интервалу (`date_histogram`) над таймлайном.
- Перенос фильтров вьювера в запрос к OpenSearch.
- Автообновление.

## 12. Проверка

Тестов во вьювере нет. Проверка по этапам:

- разбор хитов — Node-скриптом на `docs/response.json`;
- клиент OpenSearch и кэш — на заглушке OpenSearch (локальный HTTP-сервер с ответами из `docs/`);
- реальный кластер, окно и `.exe` — вручную.
